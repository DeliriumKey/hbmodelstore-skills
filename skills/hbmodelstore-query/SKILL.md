# hbmodelstore 模型查询与交互研究

**MCP 提供模型数据与方法文档，Skill 组织交互研究与绘图。** 数据与文档查询共用 `hbmodelstore` 远程 MCP。本地分析、绘图和更新脚本需要 Python 3.11+，使用标准库即可。

## 内容分工

| 名称 | 职责 |
| --- | --- |
| 模型数据 | 已计算的模型结果，通过 MCP 或 API 查询 |
| 方法文档 | 模型原理、计算方法、验证与实验依据 |
| 分析指引 | `analysis/` 中针对具体问题的比较方法、判断逻辑与后续线索 |
| 交互研究 | Agent 围绕用户问题查数、取证、判断并开展多轮交流；一次运行记录称为研究会话 |
| 面板组件 | 包含图表、表格与交互操作的完整业务展示，由对应 Reference 说明口径与调用 |
| 绘图单元 | 单张图的绘制逻辑，可供面板组件组合，也可在研究中独立调用和导出 |

以上是职责分工，按当前问题组合使用；网页导航保留交互研究、面板组件和方法文档三个入口。

## 按任务读取

按任务选择模型入口，由对应 MODEL.md 路由到查询参考或分析指引。涉及结果解读就参考相关分析指引，
只读取当前任务需要的内容。
面板组件 Reference 说明计算口径、应用场景、不适用场景及调用方式，前三部分与网页共用；
分析指引提供具体研究问题的判断依据、比较方法与后续线索，不承担完整报告的编排。
深入模型构建与验证时再查文档 MCP。

## 取数与基金身份

- 普通查询直接调用能力清单中的 `mcp_tools`，参数以客户端发现的工具 schema 为准。
  Reference 中的 CLI 示例用于保存数据、分析和绘图，不是查询的前置步骤。
- 名称不明确时用 `search_funds`；精确份额代码需要映射时用 `resolve_fund`。已有非空
  `initial_fund_code` 就复用，不重复请求；不同基金实体无法区分时再问用户，不猜 A/C 对应关系。
- 映射成功不代表模型覆盖。按模型查询参考确认可用日期、区间和结果；不要因近期没有样本就拒绝历史查询。
- 默认区间、结果语义按对应 MODEL.md 指定的资料来源读取，工具限额以发现的 schema 为准。
  空值、零值和请求失败分别处理。
- 分析或绘图优先复用完整 MCP 导出或已有快照，按对应 Reference 导入脚本，不手抄截断的工具输出。

## 交互研究与交付

- 默认承接用户当前的问题开展研究交流：先给判断，再解释关键依据，随追问继续深入。
  一个完整判断可以包含多个相互支撑的小节；按问题是否已回答决定范围，而不是按标题逐节拆分。
  需要图表时，优先配一个最贴近当前问题的面板组件 HTML，正文按论证需要选取其中的图导出 PNG，
  穿插在相关段落之间；一个面板组件可包含多张相关图表，展示范围随本轮问题决定。
  其他数据可作为判断依据，展示范围随问题展开；用户明确需要综合比较时，也可以使用多个面板组件。
- 研究时考虑当前判断在后续决策中的位置。回答后，结合本轮发现提出值得继续研究的问题，
  说明接着看什么、能帮助判断什么，并自然邀请用户选择是否深入；后续专题随用户回应展开。
  必要的数据补查仍服务于本轮判断。报告的整体组织由独立任务承接，分析指引保持问题导向。
- 采用专业投资研究的表达，平实、自然、具体地说明对象、比较依据、变化及投资含义。
  专业化是把意思说准确，不是改用抽象术语；保留主语、条件、关键过程和因果关系，
  用具体的价格、价值、配置和收益关系承载判断，将口语比喻、情绪表达和口号转述为准确内容。
- 分析时充分考虑相关证据，成文时选择能回答问题、解释原因或改变取舍的发现。
  分析指引提供推理依据，正文结构由本次发现决定；查过的指标和考虑过的问题可以留在底稿。
  篇幅随有效内容展开，以把判断讲透为准，不设字数、段落或栏目数量。
- 开头直接回答问题，后文用新的证据或比较推进论证，同一判断集中讲清。
  实质风险和适用条件在影响本次判断时就地说明。面板直接交付绘图命令生成的 HTML，
  来源、日期与读图提示沿用组件已有内容；样本筛选和计算口径由组件 Reference 与方法文档承载，
  用户专门询问时再解释。
  界面操作和绘图实现细节按用户的使用问题说明，研究正文围绕数据与判断展开。
  方法或边界的专门说明同样按用户提问展开。行动建议落在本次结果支持的具体取舍上。
  回答需要标题时，使用研究对象与议题或实际发现，例如“转债市场估值与配置价值”；
  用户的口语提问保留在对话中。图表承载数据，文字解释它们怎样支持判断。
- 涉及结果解读、比较、原因解释或判断时，读取对应的分析指引，参考其口径组织回答，
  不以用户是否明确说“分析”为触发条件。按问题选择相关内容，不要求执行完整复盘或输出全部章节、表格；
  一段简短结论也适用。仅返回数据或生成图表、不作解读时，可以不读取。
- 优先复用已有结果，只为当前判断所需补查数据；参考分析指引是为了回答当前问题。
  同时要求绘图与分析时，网页就绪后先提供链接，再继续分析。
  网页所需的取数、归因计算与校验照常完成，不因暂不撰写分析而省略。
- 纯数据查询交代必要的基金身份、实际覆盖、关键值和单位，不倾倒 JSON。文字分析直接进入判断，
  不机械重复图表已有的身份和覆盖说明。没有披露期或模型日时不补点。
- 分析表格一格一个值，保留必要单位；不在数值后拼接计数、分子分母或说明。
  额外信息确有必要时独立分列，否则省略；代码与名称分列。表头和单元格不添加加粗标记。
- 正文、表格和图表中的收益率、收益差、归因贡献都在数值后直接带 `%`，如“收益差 1.80%”；
  收益差仍按算术差计算，不改成相对增长率，也不另换成 `pp` 或“个百分点”。
- 表格呈现数值，正文解释比较结果、变化及其含义。有表时，正文默认不重复表内数值，
  也不用括号补抄或把数值串成一句；没有表时再用少量关键数字支撑判断。
- 查询、计算和绘图按对应 MODEL.md 进入 Reference；输出中涉及解读时，同时参考相关分析指引。
- **需要图表时，默认生成交互式 HTML，并优先在 Agent Harness 的侧边栏/内置网页预览中打开。**
  使用能力清单对应的绘图命令直接生成并交付面板组件网页，沿用包内同源 ECharts renderer；
  分析文字另行返回。现有面板组件未覆盖用户请求时，再说明缺口并按需扩展。
  保留各面板组件已有的交互，如图例开关、区间选择或缩放，不用静态截图替代交互页。
  若当前客户端不能预览，提供本地 HTML 文件或可访问链接；不假称已在侧边栏打开。
  研究正文需要图片时，按[绘图运行环境](./references/chart-runtime.md)从同一 HTML 导出所需 PNG，
  保留图例、坐标轴、单位和必要标注，图片不加标题、脚注或额外图注；来源与日期保留在交互 HTML。
  用 Markdown 图片语法将 PNG 直接嵌入相关段落之间；根据客户端能力使用本地路径或可访问的图片 URL。
  PNG 的区间和系列应与讨论对应，导出沿用原绘图逻辑。纯数据查询不强制出图，PDF 仍按明确要求生成。
- 原始结果需要落盘时保存 JSON，已有 JSON 时离线分析/重绘，不重复取数；分析表格可直接输出
  Markdown，不要求另存派生统计文件。大结果通过原生完整文件导出或现有取数脚本落盘，
  不能从聊天上下文拼回数据；文件放在用户工作目录或临时目录。

## 方法与更新

- 字段与计算说明：按对应 MODEL.md 指定的来源读取。
  面板组件口径读对应 Reference，模型推导与验证读文档 MCP；不复制模型手册。
- 检查或更新本地 Skill：见[自助更新](./references/update.md)，仅在用户要求时执行。

本 Skill 只消费公开结果，不运行模型或写库。
