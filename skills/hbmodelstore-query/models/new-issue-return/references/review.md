# 复盘与跟踪统计工具

本页说明工具执行与按需核对。文字分析统一读[收益回顾与可持续性](../analysis/return-review.md)；
指标与窗口定义见文档 MCP“构建方法”中的“统计区间与汇总”。

先按[查询与计算](./query.md)取得完整 `analysis.json`，其中需要 `source_rows` 和逐场景完整 `details`。
已有结果直接复用；旧结果缺 `source_rows` 时，从已有发行表重新运行 `analyze.py`，不从聊天表格拼回输入。

```bash
python "$SKILL_DIR/models/new-issue-return/scripts/review.py" \
  --input analysis.json --output review.json
```

脚本只派生事实，不重新计算打新盈亏，也不联网。省略规模参数时整理输入的所有场景；
只看已存在的1500万元场景可加 `--capital 15000000`，场景不存在则先用原测算器计算。
月度跟踪为主入口。可用 `--month 2026-08` 指定分析月，`--as-of 2026-10-10` 固定月度观察截止日以便复现，
否则按上海当天与输入 `end` 中较早者选月。`--window` 只调整辅助项目窗口的目标数量。
CLI 参数和默认值用 `review.py --help` 查看；这些参数可由用户通过Agent传入，不要求新增网页控件。

辅助项目窗口默认比较最近 10 只与此前 10 只，同一上市日的边界项目整批纳入。
最近上市距输入截止日超过 60 天，或两组项目横跨 180 天以上时，工具提示窗口近期性较弱；
这两个时间参数只用于提示，不作为风险判级。发行稀疏时采用较长参照，不强凑月度结论。

输出包含：

- `monthly_tracking.target`：分析月及项目事实；没有完整月且未指定月份时为 `null`。
- `monthly_tracking.baselines`：`previous_month`、`prior_3_months`、`prior_12_months` 三个参照。
  `start/end` 为所需日历区间，`covered_start/covered_end` 为实际覆盖区间；
  `complete_month_count` 和 `coverage_complete` 用于检查历史是否足够。
- `monthly_tracking.comparisons`：分析月相对各参照的数值变化；覆盖不全时为空，不是风险判级。
- `monthly_tracking.month_to_date`：默认选月时，附上最新不完整月份的补充观察；指定分析月时不附。
- `overall`：全输入区间的项目事实，主要用于核验。
- `recent`、`previous`、`comparison`：辅助的两组不重叠项目及差值，同一上市日整批纳入。
- `months`：逐月结果和项目数，`partial_month` 标出查询边界的不完整月；无项目月份保留。
- `cautions`：样本不足、数据不完整、陈旧及比较跨度长等判断所需信息。

指定历史月份时以该月及其参照为准；`overall`、`months` 和辅助项目窗口仍属全输入区间，
不能把分析月之后的项目作为当时的证据。需要历史时点的辅助窗口时，先将测算输入截止到该时点。

价格、配售和收益各有自己的有效数量。缺配售率但已有价格的项目仍计入价格统计，
不能只对可算收益的项目判断破发。`contribution_pp` 仅在本组收益全部可算时给值；
否则为 `null`，`known_contribution_pp` 只表示已知部分。`break_rate_pct` 的分母是 `price_count`。
百分数及其差值按结果字段标识展示，配售率已转为百分数，不要再乘100。

月度对比读取 `monthly_contribution_pp`、`monthly_issue_count` 和 `monthly_allocated_amount_yuan`；
不要拿参照组的 `contribution_pp` 多月总量当月均。覆盖不全时这些月均字段为空，
贡献缺失时贡献与获配月均为空，已观察事实仍保留在汇总字段。
无发行的完整月贡献为零，价格统计为空；没有有效价格样本不能写“没有破发压力”。

输入区间限制统计范围，工具不会自动补足被截掉的前窗。月度跟踪先确认输入覆盖分析月及其参照区间，
需要更长背景时复用完整发行表另算相应区间；发行表本身被截短时再按查询入口补取，
同时保留用户指定区间的复盘结果。沪深双打要分别讨论沪市、深市破发压力时，分别计算 `sh`、`sz` 结果。
未上市和无网下发行记录单列，空值、零值与无项目月份不混同。

## 取数与交稿检查

- `latest_listing_age_days` 是末笔上市日到输入 `end` 的天数，不是距今天数；`updated_at`
  是数据更新时刻，也不代表覆盖至该日。报告按样本截止日描述状态，不把历史快照写成实时判断。
- 月度项目用 `monthly_tracking.target.issue_ids` 或对应参照的 `issue_ids` 关联原始 `details`。
  窗口明细用 `recent.issue_ids`、`previous.issue_ids`。`months` 是完整
  日历分组，不能把它的项目数当成某个窗口内部各月数量；需要后者时按同一组身份重新分组。
- “最低贡献”“最后一次破发”等措辞，按对应字段在声明范围内排序核对；价格排序不能替代
  贡献排序。“样本内”不扩大成“市场全部历史”，无记录不自动解释为没有发行。
- 展示值由原始数值统一格式化；差值和变化率先用未舍入值计算，再舍入，不凭阅读印象抄小数。
- 数量与金额比较使用原始十进制值。申报量由除法生成时可能有末位精度差，核对约束优先比较
  名义预算和 `subscription_cap × issue_price`，不把末位差当成真实预算剩余或另创取整规则。

这些核对留在执行过程，面向用户只报告影响判断的发现，不逐条展示检查清单。
统计工具提供的是分析素材，不是报告目录；正文组织见[成稿](../analysis/return-review.md#成稿)。

## 按需核对

以下不属于日常收益回顾的必经步骤，只在用户要求或异常直接影响结论时执行。

- **规模比较**：按 `issue_id` 对齐项目，分别比较利润金额与贡献率。按构建方法的“打满额度与
  用满预算”，核对 `subscription_units / subscription_cap` 与申报金额、`capital_yuan × budget_ratio`；
  用原精度判断约束，不能从打满比例推断发行规模或账户实际资金占用。
- **实盘对照**：实际账户收益需要现金流、持仓和成本数据。构建方法的“申报与获配”采用连续数量，
  北交所实盘须使用实际获配记录；不能将余股分配带来的差额直接归因于执行或策略。
- **研报核对**：先对齐样本、渠道/类别、区间、规模、预算、价格及费用/限售假设，再逐项目核对
  配售率、上限和价格，保留对账明细与来源；未逐笔核对不声称完全一致。
