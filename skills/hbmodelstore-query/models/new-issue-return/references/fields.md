# 结果文件与交付

本页只说明如何使用脚本输出；发行表字段以公开 OpenAPI 为准，收益指标的含义从
[模型入口](../MODEL.md)指定的文档 MCP 读取。

## 从结果文件取数

- 保留 `analysis.json` 顶层的市场、区间和实际生效参数，按用户所选规模找到对应的 `scenarios` 项。
- 场景汇总用于回答区间收益，`history` 交给累计图，`details` 用于逐笔核对、排序或导出。
  不混用不同规模的汇总和明细。
- 用顶层 `sample_count`、`included` 和 `omitted` 核对覆盖；存在影响当前结论的遗漏时，
  在对应结论旁说明原因，不把正常覆盖检查逐项写入正文。
  保留原始发行表的更新与版本信息，不用生成 HTML 的时间替代数据更新时间。
- 用户要完整大表时，交付该场景的全部 `details` 字段；网页列数不限制文件交付。
  可按 `issue_id` 关联原始发行表补充源字段，不从精简网页恢复明细。

## 格式化与检查

- 数值字符串按十进制解析，空值原样保留；计算使用脚本原精度，只在展示时四舍五入。
- 万元金额由元金额除以 10000；`return_pct`、`first_day_return_pct` 直接加 `%`，
  `allocation_rate` 乘 100 后加 `%`。这些是输出格式转换，不修改原始 JSON。
- 明细收益加总后应等于场景汇总，累计末点应与同场景汇总一致；空历史不补造数据点。
- 实际参数、有效与遗漏项目数保留在结果文件，交付数据或 HTML 路径；文字报告按分析入口的
  表达要求组织，日期和单位落在表题、表头或来源注，不据此增加参数或样本说明章节。
  用户核对方法时再引用模型文档解释。
- `source_rows` 是当前市场、范围和区间的发行输入快照，包含不同价格口径和投资者类别所需字段，
  供交互 HTML 离线重算；不从某一价格口径的 `details` 还原其他口径。原始导出仍独立保存。
  HTML 调整参数后展示的是新场景，磁盘上的分析 JSON 保留生成时的参数与结果。
